# corpus

Footage/photo discovery, cataloguing, download, dedup, and shot-level
pre-processing for 911_4D. Owns `wtc4d/corpus/` and `data/manifests/`.

Everything here produces or consumes `wtc4d.schema.corpus` records
(`Source`, `Shot`, `Frame`), persisted as JSONL. **No media is ever
committed** -- `data/manifests/sources.jsonl` is metadata and pointers only;
bytes live on the Modal volume (see `infra/`) once downloaded.

## Quickstart

```bash
pip install -e ".[corpus,dev]"

wtc4d corpus registry-list                     # curated source registry
wtc4d corpus harvest --collection all          # refresh data/manifests/sources.jsonl
wtc4d corpus harvest --collection ia_911_tv_archive --limit 20   # smoke-test one collection

wtc4d corpus download --ids ia-<identifier> --dest /tmp/wtc4d-raw   # 2-3 items only, never bulk
wtc4d corpus shots --video /tmp/wtc4d-raw/<file> --source-id ia-<identifier>
wtc4d corpus dedup --videos a.mp4 --videos b.mp4 --source-ids ia-a --source-ids ia-b
```

## Architecture

| module | purpose |
|---|---|
| `registry.py` + `data/manifests/registry.yaml` | curated list of source collections: what they are, how to harvest them, license, rough size |
| `harvest/archive_org.py` | archive.org `911` TV News Archive (bulk search API) |
| `harvest/nist_foia.py` | NIST FOIA #09-42 releases + the 911datasets.org mirror (archive.org metadata endpoint) |
| `harvest/wikimedia.py` | Wikimedia Commons categories (MediaWiki API, rate-limit-aware) |
| `harvest/youtube.py` | curated search queries via `yt-dlp` metadata dumps |
| `harvest/flickr.py` | Flickr (full search needs `FLICKR_API_KEY`; falls back to the no-key public feed) |
| `harvest/noaa_usgs.py` | NOAA aerial/LiDAR + USGS/NASA satellite: hand-curated pointer `Source`s (no scriptable API found) |
| `harvest/documentary.py` | named documentary/photographic works: hand-curated pointers |
| `store.py` | JSONL read/merge/write, dedup-by-id, auto-split when the catalogue exceeds ~30 MB |
| `shots.py` | PySceneDetect shot boundaries + optical-flow camera-motion heuristic |
| `quality.py` | sharpness (Laplacian variance), blockiness, combined quality score |
| `dedup.py` | perceptual-hash (`imagehash.phash`) near-duplicate linking across sources |
| `cli.py` | `wtc4d corpus {registry-list,harvest,shots,download,dedup}` |

## Coverage, as of 2026-09-13

Generated by `wtc4d corpus harvest --collection all` (see "how to refresh"
below) -- 5,654 sources total in `data/manifests/sources.jsonl` (4.4 MB,
under the 30 MB split threshold so it stays one file).

| collection | archive | items | notes |
|---|---|---|---|
| `ia_911_tv_archive` | archive.org | 5,180 | 22 channels, ~3,403 hours; `start_localtime`+`runtime` -> `time_hint` on all but a handful |
| `ia_nist_foia_09_42` | nist_foia | 43 | releases 1-42 (some split, e.g. `r14-cus`/`r15-cus`) + 1 named clip; ~2.1 TB combined per archive.org's reported `item_size` |
| `ia_911datasets_mirror` | archive.org | 3 | hand-picked index/wiki-mirror items, not a fuzzy search |
| `wikimedia_commons_911` | wikimedia | 240 | across 5 categories; licenses: 156 public-domain, 84 various CC (by/by-sa 2.0-4.0), a few CC0/no-restrictions |
| `youtube_curated` | youtube | 129 | 8 curated search queries, metadata only, no `time_hint` (see harvester docstring) |
| `flickr_cc_911` | flickr | 50 | **no API key available** -- these are from the zero-key public recent-uploads feed, i.e. NOT a historical 2001 search (see caveat in `harvest/flickr.py`) |
| `noaa_wtc_aerial_lidar` | noaa | 1 | pointer record, no scriptable API |
| `usgs_landsat7_wtc` | usgs/other | 2 | Landsat 7 ETM+ + MISR/Terra plume analysis, pointer records |
| `commercial_satellite_ikonos_spot` | other | 2 | IKONOS pointer records, proprietary |
| `documentary_pointers` | other | 4 | Naudet, CameraPlanet, Biggart, Arellano |

Resolution mix: the TV archive is uniformly reported as 480x480 encoded
sample dimensions (SD, various true display aspect ratios per
`aspect_ratio` metadata not yet captured); NIST FOIA releases are DV/VHS/
Betacam masters digitized to DVD (MPEG2), resolution varies per tape and
is not yet parsed per-file; Wikimedia/Flickr/YouTube resolutions vary
per-item and are captured directly on each `Source` where available
(`width`/`height`).

`time_hint` coverage: 5,204 of 5,654 sources (92%) have a `time_hint` --
essentially every TV archive item plus a handful of Wikimedia EXIF hits and
the hand-dated NOAA/USGS pointers.

### How to refresh

```bash
for c in ia_911_tv_archive ia_nist_foia_09_42 ia_911datasets_mirror \
         wikimedia_commons_911 youtube_curated flickr_cc_911 \
         noaa_wtc_aerial_lidar usgs_landsat7_wtc \
         commercial_satellite_ikonos_spot documentary_pointers; do
  wtc4d corpus harvest --collection "$c"
done
```

Each harvester merges by `Source.id` (new data wins), so re-running is
idempotent and safe to do incrementally. `ia_911_tv_archive` and
`ia_nist_foia_09_42` take a few seconds each; `wikimedia_commons_911` can
take 20s-several minutes depending on MediaWiki rate limiting (429s are
retried with backoff, see `harvest/wikimedia.py`).

## Running at scale on Modal

Harvesting itself is metadata-only and fast enough to run anywhere (see
above). Bulk **downloading** (thousands of TV archive items, the ~2 TB of
NIST FOIA releases) needs the Modal volume from `infra/`, not this
environment -- there is no GPU requirement, just disk and sustained
bandwidth. The `infra` workstream exposes a `run_job(spec)` dispatcher (see
`infra/README.md`); a corpus bulk-download job spec looks like:

```json
{
  "job": "corpus_bulk_download",
  "image": "wtc4d-corpus",
  "command": ["wtc4d", "corpus", "download"],
  "args": {
    "ids": "ia-nist-foia-09-42-r01,ia-nist-foia-09-42-r02",
    "dest": "/data/raw"
  },
  "volumes": ["wtc4d-data"],
  "timeout_s": 21600,
  "resources": {"cpu": 4, "memory_gb": 16, "gpu": null}
}
```

In practice, prefer expanding `--ids` to a whole registry collection at
once (a small CLI change: accept `--collection` in `download` the same way
`harvest` does) and letting the job iterate server-side, rather than one
job per file -- 5,180 TV archive items or 43 multi-hundred-GB NIST releases
each as a separate GH Actions dispatch would be unworkably slow to launch.
This repo's own `download` command already writes `checksum_sha256` +
`bytes` back into the `Source` record on success, so the same merge-by-id
manifest update works whether it runs locally (2-3 item smoke test, as
here) or inside a Modal job against the shared volume.

## Known gaps / next sources to chase

- **NIST FOIA individual tapes.** Each of the 42 releases is catalogued as
  one `Source` (with a total byte count); the ~1,000+ individual videotapes
  inside them are not yet enumerated as separate `Source`/`Shot` records.
  Next step: for each release, list its archive.org files
  (`.rar`/`.zip` per tape) and mint one `Source` per tape referencing its
  parent release.
- **Flickr historical search.** `flickr_cc_911` currently only has the
  zero-key "recent uploads" feed, which is not useful for finding actual
  2001-era CC photos (see caveat in `harvest/flickr.py`). Getting a
  `FLICKR_API_KEY` and running `harvest_search()` (already implemented)
  should be one of the first things the next session does.
- **NOAA aerial/LiDAR actual files.** The live NOAA viewer covers
  post-2005 disasters; no working API was found for the 2001 WTC mission
  specifically. Needs direct outreach to NOAA NGS/NCEI, or a manual search
  of NOAA's historical data holdings.
- **USGS Landsat 7 exact scene.** Cited by date/time only; pulling the
  actual Level-1 product needs a (free) USGS EarthExplorer/M2M account,
  which is not available in this environment.
- **Bolivar Arellano's photographs.** No verified openly-licensed archive
  found; likely held by NY Post/El Diario/Getty-Bettmann. Worth a direct
  outreach or licensed-archive search.
- **CameraPlanet.** The original citizen-video aggregation is not
  independently reachable; only scattered archive.org mirrors are
  catalogued. Worth searching for a more complete mirror or the original
  site via the Wayback Machine.
- **Per-tape/per-video resolution and codec metadata** for NIST FOIA and
  911datasets-mirror items -- not yet parsed from archive.org file listings.
- **Shot detection and dedup have not been run at scale** -- both are
  implemented and unit-tested (see `tests/test_corpus_shots.py`,
  `tests/test_corpus_dedup.py`) but need real downloaded video to run
  against; that's naturally gated on the Modal bulk-download step above.
- **Channel identification for TV archive** relies on the `TV-<CALLSIGN>`
  collection tag; a few items may have an unrecognized or missing tag
  (falls back to the raw `contributor` field, or empty).
